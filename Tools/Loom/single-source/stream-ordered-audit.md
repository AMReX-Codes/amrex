# Stream-ordered regions: audit of AMReX's no-sync checks

`Gpu::StreamOrderedRegion` is a `Gpu::NoSyncRegion` in which multi-stream `MFIter` and `StreamIter` loops fork from and join into stream 0 on the GPU. Every place in `Src` that checks `Gpu::inNoSyncRegion()` or opens a `NoSyncRegion` was reviewed for what it relies on once the host no longer synchronizes between loops that may run on several streams. A no-sync region already promises that no host access follows a skipped synchronization (AMReX's own contract, unchanged); the new question for each site is whether it relies on work from *another* stream being finished, which the fork and join now provide on the GPU.

Summary: skip after same-stream work 118, iterator default 8, sync before host access 7, device sync for library 7, stream-ordered free 4, comment 3, async arena 3, SyncAtExitOnly 2, nested region 2, cross-stream copy 1, explicit sync kept 1. One site changed (`AMReX_FabArray.H`, cross-stream copy). A scan of the 8 lines after each skipped synchronization for device-to-host copies or host-pointer reads found none; beyond that, these sites rely on the no-sync contract they already had.

## LOOM runtime (`Src/Base/AMReX_Loom.cpp`)

| Wait | Decision |
|---|---|
| `device_free`, `pinned_free`: `sync_all()` before releasing the buffer | **Changed.** The buffer is released once every AMReX stream has passed the timeline point it had reached at the free, checked at later completion points; a failed allocation waits for the GPU and releases pending buffers before retrying (`AMREX_LOOM_FREE=sync` restores the old behavior). |
| `build_arrays`: blocking `Gpu::htod_memcpy` of the offset table | **Changed.** `Gpu::htod_memcpy_async`: the runtime stages pageable sources at the call. |
| `stream_synchronize`, `stream_query` (completion points) | Unchanged: a host wait the caller asked for. |
| Pinned staging ring full, pageable staging over its limit | Unchanged: synchronizes the stream to reuse its staging; rare (at most one per step in CNS with 8 boxes, from `StreamManager::free_async`'s 100-entry limit). |
| `stream_destroy` | Unchanged: waits for the stream before releasing its queue; pending frees drop the stream's points. |
